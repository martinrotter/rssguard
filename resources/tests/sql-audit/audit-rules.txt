Current user rules for this audit
================================

Inventory every application SQL execution site, dynamic generator and structural
variant. Arbitrary user-written SQL is an infinite family; list its execution
path and generator instead of claiming to enumerate every concrete string.

Benchmark the huge current-schema fixtures systematically. Stop at the first
potentially slow query family. Investigate and measure proposed improvements to
that family before presenting anything for approval.

Lazy loading stays optional and off by default. Preserve full-result behavior,
all columns, native ordering and label strings. Propose SQL-only changes or small
C++ refactorings that are demonstrated speedups.

Every proposal must be tested and measured on BOTH SQLite and MariaDB in the same
review cycle before approval is requested. Use comparable logical datasets and
record each engine's settings/version. Compare baseline versus candidate within
each backend, retaining that backend's existing collation and behavior.
